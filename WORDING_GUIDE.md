# StayExplore Kenya - wording guide (v9.32)

Use the same word for the same thing on every page, email and message.

| Idea | Use | Avoid |
|---|---|---|
| Person who travels | Traveller (account type), Guest (when talking about a booking) | Tourist (except inside code and the database role `tourist`) |
| Person who lists a place | Host | Property owner, lessor |
| Staff who run the site | Admin | Administrator |
| Place to stay | Stay, property | Accommodation (keep in formal report text only) |
| Tourist spot | Attraction, place | Catalogue entry, record |
| Booking | Booking | Reservation |
| Listing the admin declined | Not approved | Rejected |
| Listing waiting | Waiting for approval (host), Awaiting review (admin) | Pending moderation |
| Checking an email address | Verify your email | Confirm / authenticate / activate |
| Checking an ID | Verification (Verified host, Verified guest) | Mixing it with email verification |
| Payment not yet confirmed | Awaiting payment | Unsettled, outstanding |
| Money kept by the site | Platform commission / service fee | Deductions, levy |
| Something went wrong | Say what happened and what to do next | Technical errors, codes |

Rules for new text: short sentences, one idea each, say what to do next, no jargon, never show database or PHP errors to people.
Role values in code (`tourist`, `host`, `admin`) and database status values (`rejected`, `pending`) are not changed; only the words people read are.
